## 1. Recording-wide capture limitations

These apply to every figure. They are not repeated in each entry.

1. **Pre-existing favourites.** The trainer appears to already have several pages favourited. The recording identifies the correct menus, but may not show a clean before-and-after state for any star selection. Recording frames can confirm *location*, not *star-state behaviour* (`VG-07`).
2. **Timestamp accuracy.** Timestamps are derived, not frame-checked. Allow ±5 seconds.
3. **Privacy.** Any frame may show the legal entity name, user name or initials in the D365 header, or customer data on the page behind the navigation pane. All of these must be masked or cropped under the agreed policy (`VG-27`).
4. **Interface currency.** The recording may not match the current D365 interface. Publication screenshots must reflect the current interface (publication gate).
5. **Use of recording frames.** Use recording frames to confirm menu locations and draft placement. Publication screenshots should be recaptured in a clean D365 session (`VG-24`).

## 4. Clean-session recapture specification

Use this for every figure that is not supported by a recording frame. Use it for all publication screenshots if `VG-24` is resolved that way.

| Requirement | Detail |
|---|---|
| D365 user | A user whose Favourites do **not** already include the four pages. Removing existing favourites is not yet documented (`VG-14`), so use a user who has never added them. |
| Security role | The standard AR Collections security role (`VG-17`). |
| Environment and legal entity | A training or demonstration environment and legal entity (source 2, capture standards). |
| Language setting | The same D365 language setting learners use. This confirms **Favourites** / **Favorites** (`VG-28`). |
| Before-and-after frames | For Figures 3, 4, 5 and 7, capture the star **before** and **after** selection. This resolves `VG-07`. Keep both until the PG decides which to publish. |
| Navigation context | Show the full navigation context: navigation pane, module heading, and any menu group or submenu containing the page (`VG-02` to `VG-06`). |
| Timing | Capture the state immediately before each action (source 2, capture standards). |
| Labels | Keep menu labels fully visible and unobscured by the cursor. |
| Privacy | Mask or remove customer names, account numbers, balances, user names and any other sensitive data (`VG-27`). |
| Desktop hygiene | Do not show unrelated browser tabs, open files, notifications or desktop content. |
| Consistency | Use the same browser window size, zoom level and theme for all eight figures. |

## 5. Callout standard (proposed for reuse)

- Use one highlight style (for example, a rectangle outline) for "select this" targets.
- Number the callouts only when there is more than one per figure, and match the order in the step text.
- Do not place callouts over the label text they identify.
- Use the caption format `Figure n. <Outcome or screen name>`, in sentence case, with no full stop at the end.
